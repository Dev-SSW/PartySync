# PWA와 로그인 복원 운영 안내

## 배포

- 기존 GitHub Actions 절차로 검토 후 배포한다. OCI 접속이나 운영 DB 수동 변경은 필요 없다.
- 배포 전 기존 방식으로 PostgreSQL 백업을 확인한다. Flyway가 V4, V5를 순서대로 적용한다. V1~V3와 `ddl-auto: validate`는 변경하지 않았다.
- V4는 `group_member.active`를 기본 `true`로 추가하고 `account_refresh_token` 테이블을 만든다. V5는 만료 정리 인덱스를 추가한다. 기존 그룹·계정·멤버·일정·게시글·세션 행을 보존한다.
- `deploy/.env.prod.example`의 `ACCOUNT_SESSION_TTL=PT15M`, `REMEMBER_LOGIN_TTL=P30D`를 참고하여 운영 환경값을 검토한다. 기존 `.env`에 `ACCOUNT_SESSION_TTL=P7D`가 명시되어 있으면 **PT15M으로 변경해야 짧은 API 토큰 정책이 적용**된다. 새 TTL은 신규·갱신 세션에 적용하며 기존 만료 시각은 보존한다.
- `MEMBER_SESSION_TTL`은 기존 기본 PT12H를 유지하되 부모 계정 API 토큰 만료를 넘지 않는다. 만료된 그룹 세션은 계정으로 재발급한다.
- 운영은 Caddy와 `/api`의 같은 Origin 구성을 유지한다. CORS credentials는 여전히 비활성화되어 있다. 다른 Origin에 프론트엔드와 API를 분리하는 배포는 지원하지 않는다.
- `AUTH_COOKIE_SECURE` 기본값은 true다. Compose 운영 환경에 false를 전달하지 않는다. 로컬 HTTP 개발에서만 루트 `.env`에 `AUTH_COOKIE_SECURE=false`를 사용한다. Vite 프록시는 원래 Host를 보존한다.
- 기존 사용자에게 로그인 유지를 적용하려면 새 화면에서 한 번 다시 로그인해야 한다. 기존 43자 비회원 토큰과 이미 발급된 계정 Bearer 세션은 기존 서버 만료·폐기 시점까지 호환된다. 오래 열어 둔 구버전 클라이언트는 새로고침한다.

## 인증 정책

- API 인증은 기존 DB 관리형 Opaque Bearer 세션이다. JWT, Redis, 별도 서버를 추가하지 않았다.
- 계정 API 토큰은 sessionStorage에만 보관한다. 30일 복원 토큰은 JS에서 읽을 수 없는 `HttpOnly; Secure; SameSite=Strict`, host 전용 쿠키(`Path=/api/auth`)다. localStorage에 계정 장기 토큰을 저장하지 않는다.
- 로그인 유지 기본값은 활성화다. 해제하면 Max-Age가 없는 브라우저 세션 쿠키를 사용한다. 브라우저의 세션 복원 설정에 따라 세션 쿠키가 복구될 수 있다.
- 복원 토큰 원문은 DB에 저장하지 않는다. SHA-256 해시와 부모 세션, 최초 로그인부터의 고정 만료 시각을 저장한다. 갱신할 때 매번 교체하며 사용된 토큰의 재사용·만료는 부모와 하위 세션을 폐기한다. 고정 만료 시각은 갱신으로 연장하지 않는다.
- 서버에서 `user_session.revoked_at`을 설정하면 해당 기기의 복원도 차단된다. API `expires_at`은 짧은 접근 수명이며 장기 복원 만료는 `account_refresh_token.expires_at`으로 분리된다.
- 쿠키 변경 요청에는 `X-PartySync-Client: web`을 요구하고, Origin이 있으면 현재 요청 Origin과 정확히 일치해야 한다. Caddy가 신뢰할 프록시 헤더를 덮어쓰는 기존 설정을 유지한다. 인증 쿠키를 일반 그룹 API 인증에 사용하지 않는다.
- 탭 내 갱신은 하나의 Promise를 공유한다. Web Locks 지원 브라우저에서는 탭 사이의 쿠키 회전도 직렬화한다. HTTP 재시도는 계정 401에 한 번만 적용한다. 네트워크·5xx는 인증을 지우지 않고 재시도를 안내하며, 검증되지 않았거나 만료된 계정을 로그인 완료 상태로 표시하지 않는다.
- 로그아웃은 현재 기기의 부모·하위 세션을 폐기하고 복원 쿠키를 지운다. 다른 기기는 유지한다. 인증 응답/API는 no-store다. 만료된 refresh 행만 발급 시 최대 100개씩 정리하며 스케줄러를 추가하지 않았다.

## 참여와 강퇴 정책

- `/join/:inviteCode`에서 보유한 비회원 토큰을 서버로 검증한 뒤 이동한다. 계정은 복원 후 초대 코드에 연결된 **자신의 활성 멤버만** 조회하여 그룹 세션을 재발급한다. ID·닉네임·일정·게시글은 유지된다.
- 계정 로그인 링크는 원래 `/join/…` 경로를 `returnTo`로 보존한다. 닉네임·초대 링크만으로 다른 사람의 멤버 권한을 부여하지 않는다.
- 파티장만 같은 그룹의 일반 멤버를 비활성화할 수 있다. 자신과 다른 OWNER는 강퇴할 수 없다. 모든 비회원·계정 그룹 토큰 인증과 계정 재발급 쿼리가 활성 상태를 확인한다.
- 비활성 멤버는 인원·멤버 목록·일정 집계에서 제외한다. 일정 원본과 게시글·작성자 표시는 역사 기록으로 보존한다. 멤버를 물리 삭제하거나 기록의 작성자를 바꾸지 않는다.
- **닉네임은 비활성화 후에도 예약**된다. 기존 기록과 새 참가자의 혼동을 막기 위해 재사용을 허용하지 않는다. 계정 연결도 보존되므로 강퇴된 동일 계정의 같은 그룹 복원·재연결은 거절한다.
- 강퇴는 영구 차단 기능이 아니다. 기존 초대 링크로 다른 닉네임의 새 비회원 참여는 가능하다. 이 경우 새 멤버 ID와 빈 일정을 갖는다. 강퇴된 계정으로 자동 연결을 시도하면 충돌을 안내하며 새 비회원 참여 정보는 보존한다. 초대 링크 재발급과 영구 재가입 차단은 구현하지 않았다.

## 설치와 확인

### 홈의 내 파티와 기본 파티 실행

- 홈(`/`)은 로그인 복원 후 `/api/account/groups`에서 계정에 연결된 활성 파티를 조회한다. 그룹 토큰이 사라져도 목록은 유지된다. 이 브라우저의 비회원 파티는 `/api/members/me`로 검증해 함께 표시하며, 같은 그룹은 계정 멤버를 우선한다.
- 파티 입장 시 실제 권한을 다시 확인하고, 유효한 계정 그룹 세션이 없으면 기존 `/api/account/groups/{groupId}/session`으로 재발급한다. 새 멤버를 생성하지 않는다.
- 기본 파티는 `localStorage`의 `partysync.default-party.v1.account.{계정 ID}` 또는 `partysync.default-party.v1.guest`에 그룹 ID 숫자만 저장한다. 로그인 중의 선택은 해당 계정 범위에 저장하며 비회원 설정과 섞지 않는다. 다른 브라우저·설치 PWA의 별도 저장소와 동기화하지 않는다.
- Manifest의 `id`와 `scope`는 `/`를 유지하고 `start_url`만 `/launch`로 바꿨다. `/launch`는 인증 복원 → 기본 파티 조회 → 활성 목록과 접근 권한 검증 → 필요 시 그룹 세션 재발급 → 일정표 순서로 실행한다.
- 설정이 없거나 권한이 없으면 홈으로 이동한다. 확정적인 접근 거부·목록에서 사라진 파티는 해당 범위의 설정만 해제한다. 네트워크·서버 오류는 설정을 보존하고 재시도를 제공한다.
- 일반 홈 접속·로고 클릭에는 자동 입장을 적용하지 않는다. `/join/:inviteCode`의 기존 처리도 유지하여 초대받은 파티를 우선한다.

### 기존 설치 앱의 시작 경로 갱신

1. 배포 후 네트워크가 연결된 상태에서 사이트 또는 설치 앱을 열어 새 Manifest를 읽게 한 다음 앱을 완전히 닫고 다시 실행한다. `id`와 Manifest 경로를 유지하므로 앱 정체성은 바뀌지 않는다.
2. 시작 경로 반영 시점은 브라우저·OS 버전에 따라 다르다. 최신 Chrome의 갱신 정책은 [Chrome 공식 안내](https://developer.chrome.com/blog/improvements-to-web-app-updates)를 참고한다. 구버전 Android는 WebAPK 갱신을 기다려야 할 수 있다.
3. 계속 이전 홈(`/`)으로 시작하면 기존 아이콘을 제거한 뒤 Chrome 또는 Safari에서 홈 화면에 다시 추가한다. 제거 전 비회원 파티가 계정에 연결되어 있는지 확인한다. 재설치로 인증·저장소가 달라지면 로그인 후 기본 파티를 다시 지정한다. 비회원의 유일한 참여 정보를 지우기 위해 사이트 데이터를 초기화하지 않는다.
4. 기존 아이콘이 아직 `/`를 열어도 일반 홈을 강제로 리다이렉트하지 않는다. 홈에서 파티 입장은 계속 사용할 수 있다.

- Android: HTTPS 주소를 Chrome에서 열고 표시되는 `PartySync 설치` 또는 Chrome 메뉴의 앱 설치/홈 화면 추가를 사용한다. 설치 버튼은 브라우저가 설치 가능 이벤트를 제공할 때만 나타난다.
- iPhone: Safari에서 HTTPS 주소를 열고 공유 → 홈 화면에 추가를 선택한다. standalone 실행 시 안내를 숨긴다.
- 카카오톡: 메뉴에서 외부 브라우저로 여는 방법만 안내한다. 강제 전환·자동 앱 실행은 없다. 카카오톡·Chrome·Safari·설치 PWA는 저장소가 다를 수 있으므로 다른 환경에서는 계정으로 로그인해야 한다. 비회원은 원래 브라우저의 참여 정보를 잃으면 닉네임만으로 복구할 수 없다.
- Manifest와 192/512 PNG, maskable, Apple 아이콘을 제공한다. [Chrome 설치 기준](https://developer.chrome.com/blog/update-install-criteria)에 따라 메뉴 설치에 서비스 워커를 요구하지 않는 구성을 사용한다. 서비스 워커·Cache Storage를 만들지 않으므로 API·인증 HTML·개인정보·초대 코드를 오프라인 저장하지 않는다. Caddy의 해시 정적 assets 캐시와 HTML no-store, React Router fallback은 유지한다.
- 오프라인 일정 편집, 푸시, APK, Capacitor, React Native, 앱스토어 배포는 범위 밖이다.
- 배포 후 실제 Android/iPhone에서 설치, 앱 종료 후 계정 복원, 카카오톡 링크→외부 브라우저 로그인 후 기존 멤버 복원, 강퇴 뒤 오래 열린 탭의 접근 거부를 확인한다. 자동 테스트는 실제 기기의 저장소·설치 UI를 대신하지 않는다.
